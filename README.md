# ZappCode

**Your own tunnel. Your own agent.**

ZappCode is a native Android client for an [OpenCode](https://opencode.ai) server, with its own
interface and its own network guard. The design, the branding and the tunnel are ZAPP's. The
protocol behaviour is ported from the OpenCode desktop client, so a session opened here behaves
the way it does on a PC.

`com.zapp.net` &middot; minSdk 26 &middot; targetSdk 36 &middot; Kotlin + Jetpack Compose

---

## Install

1. Download `ZappCode-1.0.apk` from [Releases](../../releases).
2. Open it on the phone and allow install from this source when asked.
3. Launch **ZappCode**.

The APK is signed and debug-instrumentation-free. Updates install over the previous build and
keep your settings.

## How to use

**1. Guard — get an address.**
Open the **Guard** tab and tap **Repair (one tap)**. Five stages run in order and each one has
to prove itself: Disconnect, Fix WARP keys, Reconnect, Refresh route, Verify WARP. When it
finishes you have a verified Cloudflare WARP address and the tab shows your public `/64`.

**2. Chat — talk to the agent.**
Open **Chat**, pick a session from the sidebar or start a new one, and type. Replies stream in
as they arrive. Thinking is shown above the answer; tools, diffs and file rows appear inline.

**3. Long commands — move them to the background.**
When the agent starts a command that takes a while, tap **Move to background** on the running
card. The command keeps running; the turn stops being pinned to it. Everything detached lives
in the **Shell** sheet, reachable from the chip above the composer.

**4. Rotate when a route dies.**
**Rotate /64 Now** on the Guard tab gives you a new address from the pool. Rotation is
deliberately separate from Repair — repairing a route and changing identity are different
decisions.

**5. Export and import.**
Sessions export to `Download/ZAPP/` as JSON, 1 GB per file, unlimited count. Import reads from
the same folder.

## The one-tap Repair

A repair is a pipeline, not a button that fires and forgets. Every stage has to prove itself
before the next one is allowed to start:

```
Disconnect  ->  Fix WARP keys  ->  Reconnect  ->  Refresh route  ->  Verify WARP
```

- **Disconnect** waits until the OS reports no VPN transport, not until we set a flag.
- **Fix WARP keys** registers a fresh key pair and fails honestly if the API refuses.
- **Reconnect** waits for the tun device to exist.
- **Refresh route** rebuilds the pool and takes one real egress reading.
- **Verify WARP** is the only proof that counts: `warp=on` from a live `/cdn-cgi/trace`.

Measured on a Pixel-class device over Wi-Fi: **all five stages in 8–12 s**. A stage that cannot
prove itself stops the pipeline and says which one failed.

## Design

Near-black canvas, one violet accent, no grey chrome.

```
Bg #0A0A0A        Surface #0C0C0F    Surface2 #141419
Line #191920      Border #262630
Text #FAFAFA      TextMid #9A99A6    TextDim #6A6974
Accent #B7A8D2    AccentSoft #DDD4EC  AccentContainer #3A3448
Good #B7A8D2      Warn #A9A6BC        Bad #F17471
```

The ramp is deliberately **not** neutral grey: every step carries a faint violet cast so it sits
against the accent instead of reading as unfinished chrome. Icons are hand-pathed from the
OpenCode icon catalogue (`OcIcons.kt`), not stock Material glyphs — a chat bubble, a shield, a
terminal. Switches are our own hairline toggle, not Material's filled pill.

## Scripts are not shipped in plain text

An APK is a zip. `assets/serve.sh` and `assets/zapp_proxy.py` used to sit in it as readable
text — the whole launcher and the whole egress proxy, copyable in under a minute.

They are now AES-256-GCM blobs under `assets/lane/`, generated by `make-vault.js`. The key is
`SHA-256(pepper | package | version)` and the pepper is stored as XOR'd bytes in `Vault.kt`,
so it is not a literal string in the dex. The release APK contains exactly two files under
`assets/lane/` — `serve.bin` and `proxy.bin` — and no plaintext script of any kind.

This is obfuscation, not real secrecy — the phone has to decrypt the script to run it, so a
determined reverse engineer with a debugger can still recover it. What it stops is the
realistic case: unzip the APK, read the file, ship it as your own.

The plaintext sources live in `reference/lane/`, which is gitignored and never enters the APK.

## Building

```bash
# JDK 17+, Android SDK 36
./gradlew assembleRelease
```

`local.properties` must point at your SDK. The release build is signed with the local debug key
so `adb install -r` keeps app data; keystores are gitignored on purpose.

## Layout

```
app/src/main/java/com/zapp/net/
  api/        OpenCodeClient, SSE, session import

  net/        egress proxy, SOCKS5, Tor lane

  vpn/        VpnService and the WireGuard engine
  termux/     PTY bridge, vault, egress probe
```
